# Платформа контроля времени работы сотрудников

MVP системного модуля для HR-учёта занятости сотрудников. Модуль фиксирует события активности, определяет активное время и простой, периодически формирует отчёт и отправляет его на сервер отчётной системы. При недоступности сервера отчёты сохраняются локально в spool-каталог и повторно отправляются при следующей попытке.

## Бизнес-процесс

Процесс: HR-учёт занятости.

Роль модуля в процессе:

1. Рабочее приложение или системный агент передаёт в модуль события активности: клавиатура, мышь, фокус окна, heartbeat.
2. Ядро модуля агрегирует активное время и простой по правилу `idle_after`.
3. Фоновый worker не блокирует основное приложение и по расписанию формирует снимок активности.
4. API интеграции отправляет JSON-отчёт на сервер отчётной системы.
5. Если сеть или сервер недоступны, отчёт сохраняется в локальный spool и будет отправлен позже.

Такой модуль можно встроить в desktop-агент, корпоративное приложение или сервис, который уже умеет получать системные события. В текущем MVP сбор низкоуровневых событий ОС изолирован за API `record_activity`, чтобы модуль оставался независимым и переносимым минимум на macOS.

## Архитектура

Проект написан на Rust без внешних зависимостей, чтобы снизить риск проблем с поставкой, памятью и совместимостью.

Файлы и модули:

- `src/lib.rs` - публичная точка входа библиотеки и экспорт основного API.
- `src/config.rs` - конфигурация трекера и валидация входных параметров.
- `src/core.rs` - доменная логика: `EmployeeId`, события активности, агрегатор активного времени и простоя, JSON-снимок.
- `src/api.rs` - публичный интерфейс `ActivityTracker` и `TrackerHandle` для встраивания в приложение.
- `src/tracker.rs` - фоновый worker на отдельном потоке, канал команд, неблокирующая обработка событий и периодическая отправка отчётов.
- `src/reporting.rs` - интерфейс `ReportSink`, HTTP-отправка через `TcpStream`, retry-механизм и файловый fallback spool.
- `src/logging.rs` - интерфейс `Logger`, файловое логирование и stdout-логгер для замены в тестах или демо.
- `src/main.rs` - минимальный CLI-пример запуска модуля.
- `Cargo.toml` - описание Rust-пакета.

Основные границы ответственности:

- Ядро не знает о сети, файлах и потоках.
- API не содержит расчётной логики.
- Отправка отчётов заменяема через trait `ReportSink`.
- Логирование заменяемо через trait `Logger`.
- Worker изолирует многопоточность от потребителя API.

## Надёжность и системные требования

Модуль учитывает требования системного программирования:

- Валидация конфигурации: пустой сотрудник, некорректный endpoint, слишком малые интервалы.
- Без аварийного завершения в библиотеке: ошибки возвращаются через `Result`.
- Retry для сетевой отправки.
- Fallback: сохранение отчётов в локальный spool при сбое сети.
- Безопасное завершение: `stop()` отправляет финальный отчёт и дожидается worker-потока.
- Контролируемый доступ к ресурсам: используются только заданные `log_file` и `spool_dir`.
- Асинхронность через отдельный поток и `mpsc`-канал, основное приложение не ждёт сеть при записи событий.
- Кроссплатформенность: используется стандартная библиотека Rust, без привязки к системным API конкретной ОС.

Ограничение MVP: HTTP-клиент поддерживает только `http://`. Для production-версии нужно заменить `HttpReportSink` на TLS-клиент с корпоративной аутентификацией, например через отдельную реализацию `ReportSink`.

## API встраивания

```rust
use std::time::Duration;
use employee_time_tracker::{ActivityKind, ActivityTracker, TrackerConfig};

let mut config = TrackerConfig::new("emp-001", "http://127.0.0.1:8080/reports");
config.idle_after = Duration::from_secs(300);
config.report_interval = Duration::from_secs(60);

let tracker = ActivityTracker::start(config)?;
tracker.record_activity(ActivityKind::Keyboard)?;
tracker.record_activity(ActivityKind::Mouse)?;

let snapshot = tracker.flush()?;
println!("{}", snapshot.to_json());
tracker.stop();
```

## Формат отчёта

Пример JSON, который отправляется на сервер:

```json
{
  "employee_id": "emp-001",
  "active_seconds": 120,
  "idle_seconds": 30,
  "total_events": 42,
  "generated_at_unix": 1779440000
}
```

## Запуск

Требуется установленный Rust toolchain.

```bash
cargo run -- emp-001 http://127.0.0.1:8080/reports
```

CLI отправит несколько heartbeat-событий, выполнит `flush()` и напечатает текущий снимок.

## Тестирование

```bash
cargo test
```

Покрытые сценарии:

- валидация конфигурации;
- проверка допустимого формата `EmployeeId`;
- расчёт активного времени и простоя;
- разбор HTTP endpoint;
- отказ от неподдерживаемого `https://` в MVP;
- сохранение отчётов в файловый fallback spool.
